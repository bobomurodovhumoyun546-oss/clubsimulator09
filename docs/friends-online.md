# Friends and online 11v11

Open ClubSim → Do‘stlar. Accounts receive a unique username automatically; it can be changed in the panel. Search by a username prefix or exact email. Search results expose display name, username, avatar and relationship state; other users' email addresses are not returned. A friendship is only accepted through the recipient's Roziman action. Requests, accepted friendships and invitations are stored in SQLite. Pending requests and invitations can be declined or cancelled.

The host saves their current club and invites an accepted friend. Invitations last five minutes. The recipient saves their club and accepts; both use O‘yinga qo‘shilish. Each account uses its saved Starting XI, training and kit. The server validates ownership, formation, unique footballer identities and the eleven slots against the existing catalogue. It creates a single shared authoritative match, runs physics at 30 Hz with 60 Hz substeps, and accepts only the authenticated user's own team's controls. Clients exchange input/snapshots over authenticated same-origin HTTP about every 80ms and interpolate display positions. Coordinates, ownership, goals, stats and scores come from the server.

Controls: WASD, Shift, Space, E through/slide, Q long pass, Enter charge/release shot (immediate keeper punt), K switch, G keeper rush; four arrow-key skills. Touch controls are included. The existing single-player engine remains available and unchanged in its default mode; networkInputs/selectedByTeam enable two simultaneous human teams. Player card IDs are retained in cardId, with team-scoped runtime IDs to avoid collisions when the same footballer appears for both clubs.

A room waits up to two minutes for both players to join. An eight-second missing heartbeat pauses the match; rejoining restores control. A sixty-second disconnect, or explicit leave, ends with a technical result. Half-time resumes automatically after three seconds. Finished rooms remain reconnectable for fifteen minutes, then memory is released. Match rows and final scores remain in SQLite. Active simulation is in memory: a server restart interrupts an active room; friendships and pending invitations survive. Friendly matches do not change career league results, coins, training or inventory.

Run npm test and npm run lint; build with npm run build for a full installation. Both browsers must use the same running ClubSim server. The backend listens on port 5050 and serves the production build; Vite on 5180 proxies the API during development. No outbound email is sent.

Localization: the Friends tab, request/invite UI, server errors, notifications, match controls, connection states, confirmation dialog and friendly-match results follow the existing Uzbek/English/Russian language selector. Messages are stored as keys so switching language updates already visible notifications without reconnecting the match. Copy is in src/data/friendsCopy.js; online notices are translated through src/match/onlineCopy.js and ruleCopy.js.
